# Data Dictionary — Synthetic Student Journey Dataset

**All data below is synthetically generated.** No field is derived from, sampled from,
or fit to any real student, institution, or record. Distributions are chosen by hand
to be plausible and to encode a learnable (but noisy) relationship with the target, so
the ML pipeline has a real signal to find — not to represent any actual institution's
statistics.

Generated by [`src/student_journey/data/generate_synthetic_data.py`](../src/student_journey/data/generate_synthetic_data.py)
into three raw tables (grain noted per table), loaded into SQLite by
[`src/student_journey/data/ingest.py`](../src/student_journey/data/ingest.py).

## `students` (one row per student — static attributes)

| Field | Type | Description |
|---|---|---|
| `student_id` | string | Synthetic anonymous identifier (e.g. `S00001`). Not derived from any real ID scheme. |
| `entry_type` | category | `first_time` or `transfer`. |
| `program` | category | Declared program area (synthetic labels, e.g. `Business`, `Engineering`, `Social Sciences`, `Biology`, `Undeclared`). |
| `entry_term_id` | string | The term the student first enrolled (FK to `terms`). |
| `expected_program_terms` | int | Synthetic "typical time to completion" for this student's program, used only to decide when a student's final term is a graduation rather than a dropout. |
| `age_band` | category | Coarse synthetic age bracket (`18-20`, `21-24`, `25-34`, `35+`). Demographic **proxy** field, included only to demonstrate the optional subgroup-fairness analysis in Phase 3/4 — not a claim about any real population. |
| `gender` | category | Synthetic label (`A`, `B`, `C` — deliberately non-identifying codes rather than real-world categories). Same proxy purpose as above. |
| `first_gen_flag` | 0/1 | Synthetic first-generation-student indicator. |
| `distance_from_campus_band` | category | `local`, `commuter`, `remote` — synthetic proxy for commute burden. |

## `terms` (one row per academic term — a sequential calendar)

| Field | Type | Description |
|---|---|---|
| `term_id` | string | e.g. `2021FA`, `2022SP`. |
| `term_order` | int | Sequential integer so terms can be strictly ordered regardless of naming. |
| `term_name` | string | Human-readable label. |

## `enrollments` (one row per student per term the student was enrolled — the core longitudinal table)

| Field | Type | Description |
|---|---|---|
| `student_id` | string | FK to `students`. |
| `term_id` | string | FK to `terms`. |
| `term_number` | int | This student's Nth term of enrollment (1, 2, 3, ...), not the same as `term_order`. |
| `enrollment_intensity` | category | `full_time` or `part_time`. |
| `credits_attempted` | int | Credits attempted this term. |
| `credits_completed` | int | Credits successfully completed (passed) this term. |
| `term_gpa` | float | GPA earned this term (0.0–4.0). |
| `courses_withdrawn` | int | Count of course withdrawals this term. |
| `courses_repeated` | int | Count of courses this term that are a repeat of a previously failed/withdrawn course. |
| `advising_contact_flag` | 0/1 | Whether the student had a recorded advising contact this term (synthetic engagement proxy). |
| `financial_aid_flag` | 0/1 | Whether the student received financial aid this term. |
| `is_graduating_term` | 0/1 | True if this is the student's final, successful (graduating) term. Rows with this flag are **excluded from the negative class** — see below. |
| `persisted_next_term` | 0/1/NULL | **Prediction target.** 1 if the student has an enrollment row in the next sequential term for them, 0 if not and this was not a graduating term, `NULL` (excluded from training) if `is_graduating_term = 1`. |

## Target construction and leakage guardrails

- `persisted_next_term` is computed strictly from *future* enrollment existence — it
  is never used as an input feature, and no field derived from term *N+1* is used to
  predict term *N*.
- Rows where `is_graduating_term = 1` are excluded from model training/evaluation
  entirely (they are neither "persisted" nor "attrition" in a meaningful sense).
- All engineered features (Phase 2) are computed using **only** data available through
  term `N` (cumulative GPA, trend, etc. as of that term) — this is validated
  explicitly by a leakage check in `src/student_journey/data/validate.py`.

## Engineered features (added in Phase 2, computed from the above — not raw columns)

`gpa_change`, `cumulative_gpa`, `credit_completion_rate`, `cumulative_credits_completed`,
`enrollment_intensity_numeric`, `prior_term_enrolled_flag`, `academic_momentum`
(trend over the student's last few terms), `cumulative_withdrawals`,
`cumulative_repeats`. Exact definitions live in
[`src/student_journey/features/build_features.py`](../src/student_journey/features/build_features.py)
docstrings once implemented, to avoid this document drifting out of sync with code.
