# Model Card — Student Journey Intelligence Engine

Model version: `20260924-065958` (Logistic Regression). Regenerate this version by
running `python -m student_journey.models.train`; every number on this page is
copied from an actual run's output (`models/model_metadata.json`,
`models/evaluation_report.json`), not estimated.

This model card follows the spirit of Mitchell et al., "Model Cards for Model
Reporting" (2019). It documents a **portfolio/educational project**, not a system in
production use anywhere.

## Intended use

- **Decision support for academic advisors and student-success staff**, to help
  prioritize which students to proactively reach out to each term.
- Intended to surface a ranked list (via the `low`/`medium`/`high` risk category) and
  the top statistical factors behind a given prediction, as **one input among many**
  to a human advisor's judgment.
- Intended to run on the synthetic dataset generated by this repository, or on data
  with an equivalent, properly-governed real-world schema and appropriate
  institutional/privacy approval — not on real student data as-is.

## Non-intended use

- **Not** intended for automated decisions with no human in the loop — admissions,
  financial aid eligibility, academic probation, disciplinary action, or any action
  that affects a student's status.
- **Not** validated on, fit to, or representative of any real university, and must
  not be described or deployed as if it were.
- **Not** intended to be the sole basis for withholding support, resources, or
  opportunity from any student. A "high risk" score is a prompt to offer more
  support, not a prediction to act on punitively.
- **Not** fit for use with real, identifiable student data without a separate privacy,
  security, and fairness review appropriate to that context (IRB/FERPA-equivalent
  processes, access controls, consent, etc. — see "Privacy and governance" below).

## Dataset

- **Entirely synthetic and fabricated** — generated by
  [`generate_synthetic_data.py`](../src/student_journey/data/generate_synthetic_data.py)
  via a forward-in-time stochastic simulation of student enrollment. No real student,
  institution, or record contributed to any value in this dataset. Full field
  definitions: [`data/DATA_DICTIONARY.md`](../data/DATA_DICTIONARY.md).
- 4,000 simulated students, 17,897 student-term rows, 16,674 labeled rows (the rest
  excluded as graduating or right-censored — see the data dictionary's "Target
  construction and leakage guardrails" section).
- Class balance: ~86% persisted / ~14% did not persist, on the held-out test split.
- Time-aware split by calendar term: train `term_order<=12` (11,457 rows), validation
  `13-14` (2,435 rows), test `>14` (2,782 rows) — training never has access to a
  student's outcome in a "future" calendar term relative to what it's predicting.
- A secondary, **real, already-anonymized public dataset** (UCI "Predict Students'
  Dropout and Academic Success") is used elsewhere in this project only as an external
  benchmark of the *modeling approach* — it is not merged into this model's training
  data and this model card's metrics are not about it.

## Model

- **Selected model: Logistic Regression** (`class_weight="balanced"`,
  `StandardScaler` on numeric features, `OneHotEncoder` on `program` and
  `entry_type`), chosen over Random Forest by validation ROC-AUC (0.764 vs 0.753).
  XGBoost is implemented and tracked but was environment-blocked on the local
  development machine (missing `libomp`); it runs in the Docker image (Phase 7).
- **Input features** (19 total — see
  [`train.py`](../src/student_journey/models/train.py) `FEATURE_COLUMNS`): academic
  performance (GPA, GPA change, academic momentum), credit load and completion
  (attempted/completed/cumulative/rate), enrollment behavior (intensity, withdrawals,
  repeats), support signals (advising contact, financial aid), and program/entry type.
- **Deliberately excluded from input features:** `age_band`, `gender`,
  `first_gen_flag`, `distance_from_campus_band` — synthetic demographic proxy fields
  kept in the dataset only to evaluate subgroup performance after the fact (see
  "Fairness" below), never fed to the model as predictive inputs. This is a design
  choice to avoid encoding indirect discrimination into the score, not an artifact of
  the data.
- Experiment tracking: MLflow (`mlruns/`, experiment `student_persistence`).
  Preprocessing and model are one serialized `sklearn.Pipeline`
  (`models/model_pipeline.joblib`) so there is no train/serve skew.

## Metrics (held-out test set, 2,782 rows, term_order > 14)

| Metric | Value |
|---|---|
| Precision | 0.930 |
| Recall | 0.790 |
| F1 | 0.854 |
| ROC-AUC | 0.785 |
| Average precision | 0.951 |
| Brier score | 0.161 |

Confusion matrix: TN=236, FP=143, FN=504, TP=1899.
Plots: [`confusion_matrix.png`](screenshots/confusion_matrix.png),
[`calibration_curve.png`](screenshots/calibration_curve.png),
[`shap_global_importance.png`](screenshots/shap_global_importance.png).

**Calibration:** the calibration curve shows predicted probabilities running below
observed persistence rates — `class_weight="balanced"` improves precision/recall/F1
on the minority (non-persisting) class but is known to distort probability
calibration. Because of this, the model does **not** expose fixed probability
cutoffs as risk categories; `low`/`medium`/`high` are the 60th/90th percentile of the
model's own risk-score distribution on the validation set (`risk_thresholds` in
`model_metadata.json`: low_max=0.448, medium_max=0.728). On the test set this
produces a real, monotonic gradient: students the model calls "low risk" actually
didn't persist 6.1% of the time; "medium risk" 23.0%; "high risk" 48.5%.

**Fairness (subgroup performance, synthetic proxies only):** ROC-AUC by subgroup
ranges from about 0.755 to 0.818 across `age_band`, `gender`, `first_gen_flag`, and
`distance_from_campus_band` values on the test set (full numbers in
`models/evaluation_report.json`, regenerate via
`python -m student_journey.models.evaluate`). **This demonstrates the subgroup
evaluation method — it is not evidence about real-world fairness of anything**,
since every demographic value here is fabricated and the underlying data-generating
process was not designed to model any real bias pattern.

**Error analysis:** false negatives (predicted "won't persist," actually did) have
notably better academic signals (mean term GPA 2.05, credit completion 0.855) than
true negatives (GPA 1.78, completion 0.804) — consistent with the model correctly
ranking risk but missing some borderline persisters at the default 0.5 threshold, a
direct consequence of the calibration shift above. Full breakdown in
`models/evaluation_report.json`.

## Explainability

Per-prediction explanations use SHAP (`shap.LinearExplainer` for this linear model —
exact, not approximate, on the log-odds scale; see
[`shap_utils.py`](../src/student_journey/explainability/shap_utils.py)). The
additivity property (`base_value + sum(shap_values)` reconstructs the model's own
raw score exactly) is checked by an automated test
(`tests/test_explainability.py`), not just asserted. Global importance
(`shap_global_importance.png`) shows term GPA, cumulative credits attempted, and
cumulative credits completed as the dominant factors — consistent with how the
synthetic data-generating process was designed, which is a useful sanity check that
the model learned the intended signal rather than a spurious artifact.

**This model identifies statistical patterns in historical-style data. It does not
determine, guarantee, or fully explain any individual student's actual future.**
Every explanation and API response repeats this.

## Limitations

- Entirely synthetic data; no real-world validation has been or could be performed.
  Metrics describe how well the model recovers the patterns *this simulation* was
  designed to contain, not real-world predictive accuracy.
- No gap-term / stop-out-and-return simulation — every student's enrollment is
  simulated as consecutive terms until graduation, attrition, or the observation
  window ends, so `prior_term_enrolled_flag` is not yet informative (a Phase 2
  limitation already noted in `db/queries/transform.sql`).
- Probability calibration is measurably off due to `class_weight="balanced"`; a
  production system that shows raw probabilities (not just risk categories) to end
  users would need a calibration step (e.g. Platt scaling or isotonic regression) —
  not implemented here.
- Demographic proxy fields have low cardinality and were hand-authored, not fit to
  any real population's distribution — subgroup results should not be generalized.
- Single simulated "institution" with one set of enrollment dynamics; no
  cross-institution variation is modeled.
- Time-aware split covers a 20-term synthetic calendar; long-run drift over many
  more real academic years is untested.

## Ethical risks

- **Automation bias / over-reliance:** a risk score can be mistaken for a verdict.
  Mitigation: this model card, the API disclaimer, and the dashboard notice all
  restate that the model finds patterns, not futures, and that it's meant for human
  review, not automated action.
- **Punitive misuse:** flagging "high risk" must not translate into reduced
  support, opportunity, or access — that would also create a feedback loop where the
  intervention itself causes the predicted outcome. Intended use is *more* support,
  never less.
- **Fairness risk if retrained on real historical data:** real institutional data
  often encodes historical inequities (e.g., under-resourced advising for some
  groups). A model trained on such data can reproduce or amplify those patterns even
  without demographic features as direct inputs, since other features can correlate
  with them. Subgroup evaluation (as demonstrated here, on synthetic data) is
  necessary but not sufficient — real deployment needs a fairness review with
  domain and legal expertise before use.
- **Privacy:** this project uses no real student data. A real deployment would need
  data minimization, access controls, consent processes, and retention limits
  appropriate to student-record privacy law (e.g. FERPA in the US) — entirely out of
  scope for and not implemented by this repository.
- **Drift:** a real deployment would need ongoing monitoring for data drift and
  periodic re-evaluation/re-calibration; this repository implements the training and
  evaluation pipeline that such monitoring would sit on top of, but not the
  monitoring itself (see the dashboard's "Data drift" section, marked planned).
